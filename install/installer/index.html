Install or update Oscuro

FM-1: stock V15 first install uses the bundled Viroid TI test package. Check the keyboard, then click Install Oscuro. On Oscuro with FM-1 USB update support, choose an FM-1 app.bin to update.

The first install, from M-Vave's firmware, also needs M-Vave's firmware file; the page combines the two on this computer. When the keyboard already runs Oscuro, app.bin alone is enough. Same-flavour app updates keep your patches and settings; saving a backup is optional. Patches are stored per synth, so a build never overwrites another synth's patches. If the build you install cannot play some of the stored patches, the page tells you how many and offers a backup before it flashes.

Go back to M-Vave's firmware

Works from Oscuro and from any M-Vave version. If you erased the patch memory for Oscuro's synth, restore your backup first: M-Vave's firmware doesn't bring it back.

FM-1 rollback has two stages: load the restore updater, then write your stock .fwsc. Settings and Oscuro patches are cleared. Keep USB connected through both restarts.

If Oscuro refuses to update this keyboard (its flash chip failed Oscuro's write test), "Use M-Vave's updater" restarts the keyboard into M-Vave's own updater and installs the file with that. Oscuro writes nothing to the flash for this. It needs Oscuro 0.21.3 or later, and a keyboard that has run an M-Vave update before.

Send synth patches

Sends .syx, .mid, or .oscbank patch files to the keyboard's synth, or a bank an AI chat made with an Oscuro AI guide (its file, or its text pasted below). The keyboard only takes patches its synth can play: Access Virus patches need the Viroid build, DX7 patches the DX7 build. Anything else is refused before it is sent.

Make room for patches

The synth builds keep patches in the keyboard's user memory, where M-Vave's firmware keeps its own data. Oscuro never erases that data on its own, so patches are refused until you do these two steps once.

  1. Save a backup

    Reads the whole memory into a .ksua file, in 10 to 30 seconds. Keep the file somewhere safe: it is the only copy.

  2. Erase for patches

    Clears the memory so the synth can store patches there. Every patch stored on the keyboard is deleted too.

Convert patch memory

This keyboard still holds patches in the old layout, where one synth could overwrite another's. Newer Oscuro builds read patches only under each synth's own key, so they need converting once. The page first saves a backup of the whole memory, then rewrites the patches in place, and checks the result. Nothing is dropped; a patch whose slot the keyboard has since used moves to the next free slot of the same synth, and the page lists every move.

Restore a backup

Writes a .ksua file back and checks it. Do this before going back to M-Vave's firmware, or whenever you want its data back. It replaces everything in the memory, Oscuro's patches included.

Patches of other flavours

All synth builds share one patch memory, and each synth keeps its patches under its own key. When you flash a build with a different synth, the earlier synth's patches stay in the flash: this build cannot play them and they take room, but nothing overwrites them. They come back when you flash a build that plays them. Save a backup first, then remove them to free the room. A backup restores them later.

Send a test report

For testers of a test build (_test in the file names, TEST on the About screen). The keyboard counts how fast keys become MIDI, how busy it is, audio dropouts and failed saves. This reads those counts and saves them as one file to send back. It only reads: nothing on the keyboard changes. The counts start again at zero when the keyboard is switched on, so read them before unplugging it.

Watch reads every 5 seconds until you stop it: it records the busiest moments and notices restarts. Other MIDI apps can stay open on macOS; on Windows, close them first.

Patches on the keyboard

Skip the model check?

The installer normally refuses firmware made for another keyboard model. Skipping that check can help with a keyboard that reports the wrong model: a board sold under another name, or one that was flashed with the wrong firmware before.

If the keyboard really is a different model, installing can leave it unable to start or unresponsive, and the recovery dongle may be the only way back. The keyboard still checks that each file is intact before anything is written.

Installing writes only the keyboard's app area; its boot code, settings and calibration are left alone, and a file for another keyboard is refused before anything is written (unless you turn off the model check). If the keyboard loses power while writing, run the same step again. If it no longer starts, it needs the recovery dongle.
