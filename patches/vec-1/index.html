Make VEC-1 patches with an AI chat

One file per synth, written for ChatGPT, Claude, Gemini or any other AI chat. No tools, no Python: copy it, say what you want, load what you get back.

  1. Copy or download the guide. Download oscuro-vs-ai-guide.md
  2. Give it to an AI chat (paste it or attach the file) and say what you want, for example: “dark pads and basses for ambient techno”. The AI asks how many patches you want, then makes them.
  3. Get the bank back: a file, or a block of text if the AI cannot make files.
  4. Load it: in the installer's Synth patches tab, choose the file, or paste the text into “Paste text from the AI”. Then send it to the keyboard. Open the installer
What the AI can't do

The guide tells the AI to say these things at the end of its answer. Play the bank, tell the AI what to change, and load the new one.

End every answer that contains a bank with a short paragraph headed What I couldn't do, in your own words. It covers:

  • You cannot hear the sounds. The values are informed estimates from how the engine works, not tuned by ear; some patches will need adjusting on the keyboard.
  • Anything the player asked for that this engine cannot do, and what you made instead.
  • Values you had to guess, or patches you are least sure of.
  • Whether you built the file yourself, or the player has to paste your text into the installer. If the packer reported an error you could not fix, say which patch and what the error said.

Never claim that you listened to, played or tested the sounds.

For VEC-1 in particular: it plays only its 64 built-in waves (no samples), it has no effects inside the patch (no reverb, delay or chorus), and one filter type (low-pass). Say so when a request needs them.

How it works (for the curious)

The tools and starter patches named here (tools/ and patches/) come with Oscuro's firmware packages. Each guide describes the firmware as of the version in the footer.

VEC-1 is the vector synth of the Phosphor build: four oscillators, each on its own wave, mixed by a point on an X/Y pad that the vector envelope, two LFOs, velocity and the key can move. A patch is 74 numbers. You describe patches in a small JSON file, a tool turns the file into a bank, and the installer sends the bank to the keyboard. Nothing here needs the firmware source: you need rw_banks.py (in tools/, next to rw_schema.json) and Python 3. The knob layout of the synth is in ../PHOSPHOR.md; general matters (what a bank is, the patch memory, using an LLM) are in README.md next to this file.

The three steps

  1. Write my_vec.json (format below). Start from a factory set: patches/vec1/vec1_showcase.json is the same format.
  2. Build the bank; the tool checks every key, and that every value is 0 to 127, and tells you which one is wrong (it does not check each key's own range: keep to the table, the keyboard limits a higher value to the top of the range):
python3 tools/rw_banks.py build my_vec.json my_vec.oscbank --name "My VEC-1"
  1. Open the installer page, Synth patches, choose my_vec.oscbank, send. The installer switches the keyboard to VEC-1 by itself; to switch by hand, hold Oct -, press PATCH, turn K1 to VEC-1 and press >. python3 tools/rw_banks.py list my_vec.json lists the names in a file and python3 tools/rw_banks.py keys vs prints every key with its INIT value.

The JSON file

An object with "engine": "vs", an optional "bank" name, and a "patches" list (at most 128). Each patch has a name (plain ASCII, up to 10 characters) and any of the keys below. A key you leave out keeps the INIT value, so a patch lists only what makes it different. Values are whole numbers. cat and desc are notes for people; the firmware never sees them.

{
  "engine": "vs",
  "bank": "My VEC-1",
  "patches": [
    {"name": "MY PAD", "E_WAVE_A": 40, "E_WAVE_B": 24, "E_WAVE_C": 47, "E_WAVE_D": 56,
     "P_SPREAD": 50, "P_ATTACK": 85, "P_RELEASE": 100, "P_CUTOFF": 95},
    {"name": "MY LOOP", "E_WAVE_A": 8, "E_WAVE_B": 18, "E_WAVE_C": 2, "E_WAVE_D": 34,
     "E_P0X": 0, "E_P0Y": 63, "E_P1X": 63, "E_P1Y": 126, "E_P2X": 126, "E_P2Y": 63, "E_P3X": 63, "E_P3Y": 0,
     "E_R1": 58, "E_R2": 58, "E_R3": 58, "E_LOOP": 1, "P_VENV": 127, "P_SUSTAIN": 110}
  ]
}

How the sound is made

The diamond. The four oscillators sit at the corners of a diamond: A left, B top, C right, D bottom. The point (Vec X and Vec Y, 64 and 64 is the centre) decides how loud each one is: at a corner only that oscillator sounds, in the centre all four at a quarter each. Everything that moves the point moves the mix: the two knobs, Vec Env (the vector envelope), LFO 1 and LFO 2 (E_L1VEC, P_L2VEC), velocity (E_VELVEC) and the key (E_KEYVEC). Mix law picks the curve between the corners.

The vector envelope. Five points on the same diamond (0 to 126 on each axis, 63 is the middle). A note starts at point 0, travels to 1, 2 and 3 at the rates E_R1 to E_R3, and stays on 3 while the key is down; on release it travels to point 4 at E_R4. Vec Env (P_VENV) is how much of that path is added to the knob position. With Loop on, the point jumps back to the first loop point after 3 (forward loops) or runs back and forth (alt loops) while the key is held; E_REPEAT limits the passes.

The rest is a classic voice: four-pole or two-pole low-pass filter with its own envelope, an amplitude envelope, two LFOs, up to 8 voices.

Recipes

  • Pad: four different families, long attack and release, P_SPREAD 40 to 60, a slow LFO 2 on the vector (P_L2RATE 10 to 20, P_L2VEC 80 to 110).
  • Pluck or bell: P_SUSTAIN 0, P_DECAY 60 to 90, a filter envelope (P_FENV above 100, E_FD 40 to 60) or a vector envelope that starts bright and ends mellow.
  • Arpeggio from one key: tune the four oscillators to a chord (E_COARSE_* 12, 16, 19, 24), put the envelope points on the four corners and turn on a forward loop (E_LOOP 1) at rates around 56. See ARP CHORD.
  • Drone: E_OCT 0, P_ATTACK 90, P_SUSTAIN 127, a very slow LFO 2 on the cutoff (E_L2CUT).
  • Bass: E_OCT 1, E_VOICES 1, one saw and one pulse near the corners, P_CUTOFF 50, P_RESO 30 and a filter envelope pluck.
  • Wobble: E_L2CUT 100 and P_L2RATE about 70 for 1.5 Hz, high P_RESO.

Asking an LLM

Paste the key list (python3 tools/rw_banks.py keys vs), the "How the sound is made" and "Scales" sections above, and ask for a JSON file in the format shown. Tell it to use only those keys, whole numbers inside the ranges, names of at most 10 characters, and to list only what differs from INIT. Build the file with the tool: it names every key or value it refuses.
