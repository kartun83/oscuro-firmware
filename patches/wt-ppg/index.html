Making your own WT PPG patches (by hand or with an LLM)

The WT PPG engine of the Retrowave and Phosphor builds stores a patch as 50 numbers. You describe patches in a small JSON file, a tool turns the file into a bank, and the installer sends the bank to the keyboard. Nothing here needs the source code: you need wtppg_bank.py (in tools/ of the package) and Python 3. General matters (banks, the patch memory, using an LLM) are in README.md next to this file.

In the builds: Retrowave, Phosphor

The tools and starter patches named here (tools/ and patches/) come with Oscuro's firmware packages. Each guide describes the firmware as of the version in the footer.

The three steps

  1. Write my_patches.json (format below). An LLM can write it for you: see Asking an LLM.
  2. Build the bank (the tool checks every value and tells you which one is wrong):
python3 tools/wtppg_bank.py json my_patches.json my_patches.oscbank --name "My WT PPG"
  1. Load it: open the installer page, Synth patches, choose my_patches.oscbank, send. The installer switches the keyboard to WT PPG by itself; to switch by hand, hold Oct −, press PATCH, turn K1 to WT PPG and press >. Every engine keeps its own patches in the keyboard's patch memory; the user guide's Patch memory backup explains the first send. The installer's three WT PPG banks are built the same way: the twelve starter patches (tools/wtppg_bank.py), WT PPG Atmospheres (patches/wtppg/wtppg_atmospheres.json: pads, drones and textures that move through the tables) and WT PPG Bass & Lead (patches/wtppg/wtppg_bass_lead.json: basses, leads and struck sounds). Copy their style; "cat" and "desc" in a patch are notes for readers and are not sent.

The JSON file

A list of patch objects. Each has a name (plain ASCII, up to 10 characters) and any of the parameter keys below. A key you leave out keeps the INIT value, so a patch lists only what makes it different. Values are whole numbers. At most 128 patches per file.

[
  {"name": "WARM PAD", "P_TABLE": 12, "P_POS": 50, "P_CUTOFF": 90, "P_ATTACK": 85, "P_SUSTAIN": 110, "P_RELEASE": 95,
   "P_DETUNE": 72, "E_TABLE_B": 13, "E_POS_B": 45},
  {"name": "SHORT PLK", "P_TABLE": 8, "P_POS": 25, "P_SWEEP": 100, "P_CUTOFF": 90, "P_SUSTAIN": 0, "P_DECAY": 52,
   "E_PD": 45, "E_PS": 0}
]

How a patch sounds: the signal path

Two oscillators, A and B, each plays a wave from a table at a position. The A and B sounds are mixed (P_MIX), run through a resonant filter, then the amplitude envelope. A position envelope (EDIT section POS) can sweep the wave position while a note sounds (that is the PPG's signature); the filter envelope (EDIT section FENV) moves the cutoff; one LFO can move the position, the pitch and the cutoff.

Tables. There are 32 (P_TABLE, E_TABLE_B), eight key waves each; the position runs along the eight and blends between neighbours. A table is a family and a variant (A to D), the number is family * 4 + variant:

TablesFamilyWhat it is
0 to 3SawSweepa saw whose upper harmonics open up as the position rises: sine to full saw
4 to 7SqrSweepthe same with odd harmonics only: sine to square
8 to 11PWMa pulse whose width narrows as the position rises
12 to 15Formanta resonant peak that moves up the spectrum: vowel-like, glassy
16 to 19FMtwo-operator FM, the index grows with the position: bells and metal
20 to 23SyncSweepa hard-sync style sweep
24 to 27Organdrawbar-like stacks: more registers with the position
28 to 31Morphblends between two random spectra: textures

The variants differ in the spectral slope or the ratio (A is the most conventional). The tables are generated for this engine, not copies of any instrument's ROM.

Scales. Times (attack, decay, release, LFO delay and fade) are exponential: 0 is 2 ms, 64 about 0.2 s... 127 about 16 s. Sustain levels are 0 to 127 linear. Bipolar values (marked centre 64) mean no effect at 64, negative below, positive above.

Every parameter

P_* are the 16 knob parameters (PARA and FX pages); E_* are on the EDIT page (hold PARA, press >). INIT is the default.

Also live from the controllers, not stored in a patch: the mod wheel (CC 1) adds vibrato, the pedal (CC 64), expression (CC 11), pitch bend and pressure (pressure opens the filter). CC 70 position, 74 cutoff, 71 reso, 73 attack, 75 decay, 79 sustain, 72 release and 7 level move the matching knobs.

Recipes to start from

  • Percussive or bell: P_SUSTAIN 0, P_DECAY 50 to 90, an FM table (16 to 19), P_SWEEP high with a short position decay (E_PD 40 to 70, E_PS 0): the timbre starts bright and settles.
  • Pad: slow attack and release (P_ATTACK 80 to 100, P_RELEASE 90), a Formant or Morph table, a little P_LFOPOS, P_DETUNE 70 to 75 for width, P_FIDELITY 2.
  • Bass: E_OCT_A and E_OCT_B at 1 (an octave down), a SqrSweep or PWM table, P_CUTOFF 60 to 80, P_FENV 85 to 100 with a short filter decay (E_FD 40 to 50, E_FS 10 to 20), E_KEYTRK low.
  • Lead: P_FIDELITY 0 for grit, P_RESO 50 to 65, E_LPITCH 15 with E_LDELAY 50 and E_LFADE 40 for a vibrato that arrives after the note starts.
  • Evolving texture: E_LSHAPE 5 (random) or 1 with P_LFOPOS 80 or more, long attack and release, two different Morph tables for A and B.

Asking an LLM

Give it this guide (or the parameter table and the JSON example) and a prompt like the one below. Ask for the JSON only, build it with the command above, listen, then go back with what you heard ("the second patch is too bright and the attack clicks"): that loop works better than asking for a perfect bank at once.

You write patches for the WT PPG synth engine described in the guide below. Reply with only a JSON list (no explanation, no code fence) of N patches. Each patch is an object with "name" (plain ASCII, at most 10 characters, upper case) and a subset of the parameter keys from the table, whole numbers inside the stated ranges; leave out a key to keep its INIT value, and only list what makes the patch different from INIT. Use the table families to choose P_TABLE and E_TABLE_B (choose different tables for A and B on most patches), use P_SWEEP/P_FENV/P_DETUNE/P_MIX and the position envelope to give each patch movement, and keep P_LEVEL at 90 or more with P_RESO below 100 so a patch is neither silent nor clipping. Make the N patches clearly different from one another in character. The sounds I want: (describe them here: e.g. "a glassy pad, a rubbery bass, a bell, a brassy lead, an evolving texture").

(paste the guide here)

The tool names the first value that is out of range or misspelled (unknown parameter ['P_CUTOF']), and you can paste that line back to the LLM.

Limits

The file builds a bank of up to 128 patches; the keyboard's patch memory keeps every engine's patches apart, and all engines share its room. Names are 10 characters of plain ASCII. Parameters are whole numbers; a value out of its range is refused by the tool (the keyboard itself would limit it to the range). The oscillators play the 32 built-in tables: there is no way to load your own waves yet.
