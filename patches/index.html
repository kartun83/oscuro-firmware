How it works (for the curious)

The tools and starter patches named here (tools/ and patches/) come with Oscuro's firmware packages. Each guide describes the firmware as of the version in the footer.

This folder has one guide per synth engine. Start here for what every engine has in common, then open the guide of the engine you want.

What you are making

A patch is one sound of one engine: a short list of numbers (50 to 143, depending on the engine; 416 for a drum kit) and a name of up to 10 plain ASCII characters. A bank is a file of patches for one engine, with the extension .oscbank. The installer's Synth patches tab sends a bank to the keyboard's patch memory; you then choose patches with Left/Right on the home screen or from the PATCH page.

Every engine keeps its own patches (0.87.4 and newer): each stored patch is tagged with its engine, so bank 1 of WT PPG and bank 1 of Juno are different patches and sending one engine's bank never overwrites another's. The engines share the room of the patch memory. On a build with several engines, sending a bank switches the keyboard to that bank's engine; to switch by hand, hold Oct -, press PATCH, turn K1 to the engine and press >. The first time, the user guide's Patch memory backup section explains how to save and erase the memory that holds M-Vave's own data. A bank holds up to 128 patches (drum kits and CZ-1 tones: 16 per bank, DX7 voices: 32); a file with more continues into the next bank.

The workflow

  1. Describe the patches in a JSON file, by hand or with an LLM (below). A patch lists only what makes it different from the engine's INIT patch; a key you leave out keeps the INIT value.
  2. Build the bank with the engine's tool. The tools refuse an unknown key and tell you which one is wrong. wtppg_bank.py and os_bank_gen.py also check every value against its range; rw_banks.py (VEC-1, DWO-1) checks that values are 0 to 127, and the keyboard limits a value above a key's own range to that range's top.
  3. Send the .oscbank from the installer page (Synth patches); the same tab's Starter bank list sends the ready-made banks.
  4. Listen and edit. The numbers are chosen from the structure of the synth; your ears decide. Change the JSON and rebuild: sending a bank again replaces the patches in the slots it covers (the installer can also replace the whole bank or append to its free places). You can also edit a patch on the keyboard and save it: hold Oct - and press Right (Right again overwrites the stored patch, Left stores a copy).

Nothing here needs the firmware source: the tools in tools/ and Python 3 are enough.

Asking an LLM

Every JSON-in engine guide ends with a section Asking an LLM. The recipe is the same everywhere:

  • paste the engine's guide sections How the sound is made, Scales and the key table (or the output of the tool's keys command) into the chat;
  • say what you want in words ("twelve slow evolving pads, three of them dark"), and ask for JSON in the format of the guide's example, nothing else;
  • tell it to use only the listed keys, whole numbers inside the ranges, names of at most 10 characters, and to list only what differs from INIT;
  • build the file with the tool and fix what it refuses; send, listen, tell the LLM what to change.

The quickest way is one file per engine written for an AI chat: ../llm-guides/ (the AI builds the bank itself, or gives you text that the installer turns into a bank).

File formats, for the curious

  • .oscbank: 43-byte header (OSBK, version 1, the two-letter engine id, a 32-byte bank name, the patch count, the bytes per patch), then the raw patches back to back. The engine ids are wp (WT PPG), vs (VEC-1), es (DWO-1), jn (Juno), mg (Moog), mt (MT drums) and va (Viroid; version 2 adds an FX rack per patch).
  • SysEx for single patches: F0 7D 4B 53 02 <two letters> <patch bytes> <checksum> F7; the installer uses it for you.
  • DX7 .syx bulk dumps (32 voices) and Access Virus single dumps (.syx or .mid) go to their engines unchanged.
