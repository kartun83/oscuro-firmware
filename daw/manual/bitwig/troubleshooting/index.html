The screen never changes to the Device view

The script has not reached Oscuro firmware.

  1. Is Oscuro running? Tap Globe → About. It should show DAW (or DAW BT). On M-Vave's firmware the Oscuro script waits and does nothing: use M-Vave's stock script there.
  2. Is the controller enabled and on the right port? Settings → Controllers: SMK-37 Oscuro with SMK-37 Oscuro USB (USB Ports: One), the DAW port (USB Ports: Split) or SMK-37 Oscuro BLE as both input and output.
  3. Is another app holding the port? Close the web installer, the preset editor and MIDI Suite.
  4. Look at the script console. In Bitwig, the controller's console prints "SMK-37 Oscuro: waiting for Oscuro firmware" until the keyboard answers.
  5. Is Bitwig new enough? The script needs Bitwig Studio 6.1 or newer; an older Bitwig shows SMK-37 Oscuro needs Bitwig Studio 6.1 or newer.
  6. Turn the controller off and on in Bitwig, or replug the cable.

Knobs, pads or SEQ do the wrong thing

  • Two scripts on one port. If M-Vave's stock script is also enabled on the keyboard's port, both react. Disable the one you are not using (stock script for stock firmware, SMK-37 Oscuro for Oscuro).
  • A keyboard page is open. While Globe settings, a SCALE / ARP / CHORD list or the Harmony Helper is up, the knobs or Left / Right belong to it. Close it.
  • The pads play notes instead of tracks. You are on pad bank A. Press Knob Bank and Fader Bank together for bank B.
  • The pads flip device switches instead of muting tracks. In the Device view a device with on/off switches takes pad bank B (the status bar shows | pads). Tap SEQ to the Mixer for the track pads.
  • The pads show drum sounds or steps. A Drum Machine is selected, or is the track's first instrument: see Drum pads and steps. Shift pad + Left leaves the steps; the Mixer has the track pads.
  • SEQ opens the sequencer. SEQ button is set to Firmware sequencer.

A fader does nothing

Soft takeover: the fader waits until it passes the track's value. Move it toward the arrow (F2^ up, F2v down) or set Fader pick-up → Jump.

Keys play twice, or not at all

  • With USB Ports: Split, add the Keys and Pads ports as generic MIDI keyboards; the script itself only listens to the DAW port.
  • With USB Ports: One, do not also add the same port as a generic keyboard: the notes would arrive twice.

Bluetooth feels slow

Bluetooth MIDI adds a few milliseconds, and its packets come in bursts, so meters and the play position look jumpier than over USB.

  • Set the script preference Connection to Bluetooth: it sends less per update.
  • Use USB for playing; Bluetooth is fine for mixing and browsing.
  • Keep the keyboard close to the computer, away from Wi-Fi routers.
  • If it stays slow, switch BT off and on, or remove and pair SMK-37 Oscuro BLE again.

The keyboard restarted, or the cable came out

Nothing to do: the script notices within a second that the keyboard is back and sends it everything again. The keyboard, on its side, drops the script's controls two seconds after the link goes quiet and returns them to their normal functions, so nothing is left hanging.

Reporting a problem

Note the version (Globe → About), what you did and what you expected. A test build can also save a diagnostics report (TESTING.md in the package). If you need the keyboard working right away, put M-Vave's firmware back with the installer.
