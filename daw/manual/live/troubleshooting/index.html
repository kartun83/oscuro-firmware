The screen never changes to the Device view

  1. Read Live's status bar. Oscuro firmware not found: the keyboard runs other firmware, or the wrong port is chosen. SMK37 Oscuro needs Live 12 or newer: update Live.
  2. Is Oscuro running? Tap Globe → About: it should show DAW.
  3. Is the control surface set up? Settings → Link, Tempo & MIDI: SMK37_Oscuro with the keyboard's only port (USB Ports: One), the DAW port (USB Ports: Split) or SMK-37 Oscuro BLE as both Input and Output.
  4. Is the folder in the right place? The .py files must sit directly in Remote Scripts/SMK37_Oscuro/. If SMK37_Oscuro is missing from the Control Surface list, the folder is in the wrong place or nested one level too deep.
  5. Is another app holding the port? Close the web installer, the preset editor and MIDI Suite.
  6. Choose None in the Control Surface row and SMK37_Oscuro again, or replug the cable.

The screen says Host lost

The keyboard got more data than its MIDI input could take, or the link was quiet too long. Lower flush_budget in user_settings.py (Bluetooth especially), and re-select the control surface.

Knobs, pads or SEQ do the wrong thing

  • Two surfaces on one port. A stock-firmware script in another Control Surface row on the same port reacts too. Set that row to None.
  • Remote is on for the keyboard's ports. In the MIDI port list, set the keyboard's ports to Remote: Off; only the control surface row talks to the DAW port.
  • A keyboard page is open. Close Globe settings, a SCALE / ARP / CHORD list or the Harmony Helper.
  • The pads play notes instead of tracks. Press Knob Bank and Fader Bank together for bank B.
  • The pads show switches, drums, steps, slices, Looper or variations. The selected device decides (Device view). Tap SEQ to the Mixer for the track pads; Shift pad + Left leaves the steps.
  • The pads show clips. The bottom-row action is Clips: Oct- + pad 9 for Mute.
  • SEQ opens the sequencer. seq_views is False.

A fader does nothing

Soft takeover: move it toward the arrow (F2^ up, F2v down), or set soft_takeover to False.

Keys play twice, or not at all

Set the keyboard's Keys and Pads ports (or its only port) to Track: On so they play. If you also route the keyboard into a track by another input, the notes arrive twice.

Bluetooth feels slow

Bluetooth adds a little delay and sends in bursts. Use USB for playing; lower flush_budget if the screen stutters or the link drops; keep the keyboard close to the computer.

The keyboard restarted, or the cable came out

Nothing to do: the script notices that the keyboard is back and sends it everything again. The keyboard drops the script's controls two seconds after the link goes quiet, so nothing is left hanging.

Reporting a problem

Note the version (Globe → About), what you did and what you expected. A test build can also save a diagnostics report (TESTING.md in the package). If you need the keyboard working right away, put M-Vave's firmware back with the installer.
