DAW manual · The surface

When the keyboard's own pages take over

The script owns the knobs, faders, pad bank B and a few buttons. The rest stays the keyboard's, and while you use one of the keyboard's own pages it borrows the knobs and Left / Right back. You never have to disconnect the script to change a keyboard setting.

Buttons that always stay the keyboard's

Globe (settings), PATCH (Harmony Helper), ARP, SCALE, CHORD, NOTE REPEAT, Oct+ / Oct-, Knob Bank, Fader Bank, BT, PARA and FX keep their own functions in a DAW session. The keys, pad bank A and the wheels keep playing MIDI.

The faders stay the DAW's throughout, and the keyboard's own fader screen never opens for them.

A turn or press that the keyboard took never reaches the DAW, so a setting you change on a keyboard page never moves a parameter by accident.

The Harmony Helper and the screen

While the Harmony Helper is on, its screen replaces the DAW view. Its pads are pad bank A, so pad bank B still controls tracks. Hold PATCH to switch it off; the DAW view returns. See Harmony Helper.

SEQ and the keyboard's sequencer

In a DAW session SEQ changes the screen view, and SEQ PLAY / SEQ REC drive the DAW's transport. If you would rather use the keyboard's step sequencer with SEQ, give SEQ back to the keyboard in the script's settings (Bitwig: preference SEQ button → Firmware sequencer; Live: seq_views: False in user_settings.py; FL Studio: seq_views: False in oscfl_settings.py). The views then stay on Device (only SEQ changes them), and SEQ PLAY / SEQ REC still belong to the DAW.

The Harmony Helper's Memory page is the one exception for SEQ PLAY: there it starts and stops the replay of your stored chords on the keyboard, even in a DAW session.
